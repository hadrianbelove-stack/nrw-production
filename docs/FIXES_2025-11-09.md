## 1. HARDCODED LOCALHOST FIX ✅

### Problem
Public site (`assets/app.js`) fetched filter data from admin panel using hardcoded `http://localhost:5556/filter-data`, which breaks when:
- Deployed to production (localhost = user's computer, not server)
- Admin and site on different machines
- Different port configurations

### Solution
Embedded hidden/featured arrays directly in `data.json`:

**Files Changed:**
- `generate_data.py:3056-3065` - Now includes `hidden` and `featured` arrays in output
- `generate_data.py:3292` - Modified `apply_admin_overrides()` to return filter arrays
- `assets/app.js:25-31` - Removed fetch to localhost, reads from data.json instead

**Before:**
```javascript
// assets/app.js
const [movieResponse, filterResponse] = await Promise.all([
    fetch('data.json'),
    fetch('http://localhost:5556/filter-data')  // ❌ Hardcoded localhost
]);
```

**After:**
```javascript
// assets/app.js
const movieResponse = await fetch('data.json');
const data = await movieResponse.json();
this.hiddenMovies = data.hidden || [];  // ✅ Reads from data.json
this.featuredMovies = data.featured || [];
```

**data.json structure (new):**
```json
{
  "generated_at": "2025-11-09T...",
  "count": 221,
  "movies": [...],
  "hidden": ["12345", "67890"],
  "featured": ["11111"]
}
```

### Impact on Launcher
**NO CHANGES NEEDED** - `launch_all.sh` continues to work as-is:

- Public site (3000) still serves static files
- No cross-origin requests needed anymore

## 2. JSON VALIDATION ✅

### Problem
Admin panel `/update-movie-fields` endpoint accepted arbitrary JSON without schema validation, risking:
- Data corruption from malformed requests
- Accidental submission of unexpected fields
- No length limits on text fields

### Solution
Added comprehensive schema validation with `validate_movie_update_request()` function:

**File Changed:**
- `admin.py:347-451` - New validation function
- `admin.py:961-965` - Validation call added to endpoint

**Validation Rules:**
| Field | Rules |
|-------|-------|
| `movie_id` | Required, non-empty string or int |
| `rt_score` | Optional, integer 0-100 |
| `year` | Optional, integer 1900-2100 |
| `runtime` | Optional, integer 1-500 minutes |
| `director`, `country` | Optional, max 200 chars |
| `synopsis` | Optional, max 5000 chars |
| URLs (rt_link, trailer_link, etc.) | Optional, must start with http:// or https:// |
| `digital_date` | Optional, ISO format YYYY-MM-DD |
| `watch_links` | Optional, dict with streaming/rent/buy keys |
| Unknown fields | **Rejected** with error message |

**Example Validation:**
```python
# ❌ REJECTED - Unknown field
{
  "movie_id": "12345",
  "hacker_field": "malicious"
}
# Error: "Unexpected fields: hacker_field"

# ❌ REJECTED - Too long
{
  "movie_id": "12345",
  "director": "A" * 300
}
# Error: "director must be 200 characters or less"

# ✅ ACCEPTED - Valid request
{
  "movie_id": "12345",
  "rt_score": 85,
  "director": "Christopher Nolan"
}
```

### Testing

```bash
  -H "Content-Type: application/json" \
  -d '{"movie_id": "12345", "unexpected_field": "test"}'
```

## 3. FILE LOCKING ✅

### Problem
Race conditions when multiple processes write to `movie_tracking.json` simultaneously:
- `generate_data.py` marks movies as enriched
- `admin.py` saves manual edits
- If both run at once, last write wins (data loss)

**Evidence:** Bulk enrichment flag corruption detection code exists because corruption already happened.

### Solution
Created `file_lock.py` module with cross-platform file locking:

**New File:**
- `file_lock.py` - Complete locking utility (254 lines)

**Files Updated:**
- `admin.py:24` - Import new locking functions
- `admin.py:346` - Removed old `safe_write_json`, now imported from `file_lock.py`

### Features

**1. Safe Locking with Timeout:**
```python
from file_lock import safe_write_json_atomic

# Write with 5-second timeout (won't hang forever)
safe_write_json_atomic('movie_tracking.json', data, timeout=5.0)
```

**2. Cross-Platform:**
- Unix/Linux/macOS: Uses `fcntl` (advisory locking)
- Windows: Uses `msvcrt` (mandatory locking)
- Fallback: Works without locking if neither available (logs warning)

**3. Lock Only During Write:**
```python
# ❌ BAD - Would freeze admin panel
with file_lock:
    # ... wait for user input ...
    # ... make changes ...
    write_file()

# ✅ GOOD - Lock only during file operation
# ... do work without lock ...
with file_lock:
    write_file()  # Brief lock (milliseconds)
```

**4. Error Handling:**
- Timeout after 5 seconds → raises TimeoutError
- Automatic lock release (even on exceptions)
- Temp file cleanup on failure

### Safety Guarantees

✅ **Admin panel won't freeze** - Locks only held during actual file write (< 100ms typically)
✅ **Concurrent operations safe** - Second process waits for first to finish
✅ **Failed locks logged** - Timeout errors logged with context
✅ **Backwards compatible** - Old `safe_write_json(filepath, data)` calls still work

### Testing
```bash
# Terminal 1: Start long-running generate_data.py
python3 generate_data.py &

# Terminal 2: Immediately try to save admin changes
curl -X POST http://localhost:5556/update-movie-fields \
  -H "Content-Type: application/json" \
  -d '{"movie_id": "12345", "director": "Test"}'

# Expected: Second request waits for lock (up to 5 seconds), then succeeds
# Before fix: Second request would overwrite first (data loss)
```

### Lock Acquisition Timeline

## File Locking Implementation Details

### Architecture

```
file_lock.py
├── safe_file_lock()         # Context manager for locking
├── safe_write_json_atomic() # Atomic write with locking
├── safe_read_json_locked()  # Read with locking
└── safe_write_json()        # Legacy wrapper (backwards compat)
```

### Usage Examples

**Basic Write (with locking):**
```python
from file_lock import safe_write_json_atomic

data = {'movies': {...}}
safe_write_json_atomic('movie_tracking.json', data, timeout=5.0)
```

**Read with Locking (for concurrent reads):**
```python
from file_lock import safe_read_json_locked

data = safe_read_json_locked('movie_tracking.json', timeout=5.0)
```

**Manual Locking (advanced):**
```python
from file_lock import safe_file_lock

with open('movie_tracking.json', 'r+') as f:
    with safe_file_lock(f, timeout=5.0, operation="update enrichment flags"):
        data = json.load(f)
        # ... modify data ...
        f.seek(0)
        f.truncate()
        json.dump(data, f, indent=2)
```

### Lock Behavior by Platform

| Platform | Lock Type | Blocking | Process Death Behavior |
|----------|-----------|----------|------------------------|
| Unix/macOS | fcntl advisory | Non-blocking | Lock released automatically |
| Windows | msvcrt mandatory | Non-blocking | Lock released automatically |
| Other | None | N/A | Logs warning, proceeds without lock |

### Timeout Handling

```python
try:
    safe_write_json_atomic('file.json', data, timeout=5.0)
except TimeoutError as e:
    logger.error(f"Could not acquire lock after 5 seconds: {e}")
    # File NOT written - original remains intact
    # Retry logic or user notification can go here
```
